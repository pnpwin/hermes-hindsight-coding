# Hermes Hindsight Coding

An independent Hermes adapter for the pinned Hindsight Coding Agents engine. The selected profile can use it to share project banks with Codex instead of using the general-purpose native Hindsight provider. This does not migrate or merge existing memory. See [installation and rollback](docs/activation.md).

An explicit canonical `$HOME` entry in `allowed_roots` grants only a session starting at that directory outside Git; it does not grant descendants or permit a route change on `cd`. Other approved Git and non-Git directories keep their existing routing, including the non-Git starting-directory fallback.

`create_missing_banks: true` (default false) lets a fresh, positively scoped session provision its exact canonical `coding-agent::…` bank on first memory prefetch. **Enable only after verifying that the running Hindsight server has no `HINDSIGHT_API_DEFAULT_BANK_TEMPLATE`.** A configured server template can create directives, change retain configuration or queue model refreshes even with an empty PUT. The public API does not attest template absence; opting in records that the operator checked it against the serving process, and must be revisited if the server configuration changes. On the reviewed Hindsight API 1.2.1, the bridge requires a matching missing-bank 404, a live session grant, a literal empty PUT and successful bank readback. Other versions do not get an automatic PUT. This opt-in is independent of `writes` and neither uploads a transcript nor installs a retain strategy. An existing bank's configuration is not updated. A noncanonical mapped bank must be provisioned separately.

See [Git seed and survey ownership](docs/survey.md) for the opt-in dedicated-bank path. Existing shared banks keep Codex as their sole seed and survey writer.

When the selected profile sets `writes: true`, eligible fresh primary local sessions can write to any bank resolved within its workspace scope, subject to effective Coding Agents `retainSessions`. By default the bank needs a `conversation` strategy; `allow_bank_default_strategy: true` permits the verified Hindsight 1.2.1 fallback for an absent strategy. The request still uses `conversation`, and the adapter does not modify bank configuration. Unsupported versions and malformed strategy definitions do not qualify for fallback. Retain uses only the memory manager's scrubbed completed-turn feed. The private cursor may briefly hold redacted append text for exact retry; a restarted or resumed session without verified lineage stays read-only. A submitted async operation is not proof of completed extraction. Ambiguous rewind snapshots and standalone `data:` markers are rejected.

For the read-only oracle, pass an explicit venv interpreter that already has `mcp`: `/usr/bin/python3 scripts/py-test.py --python "$VENV_PYTHON" test_codex_oracle.py`. This bypasses Hermes bootstrap and its profile lock writes. Both MCP bundles are required. The oracle calls only `hindsight_diagnose` using a fixture HOME, diagnostics paths, temporary config, and an unused loopback endpoint; it does not contact the production Hindsight API. The plain runner without `--python` is reserved for tests that need the Hermes bootstrap.

Hermes 0.23.3 does not forward the session's terminal policy over the out-of-process plugin-host RPC. The provider intentionally stays inactive there and whenever a bound policy does not positively name the local backend. This does not change the user's isolation settings.

The read surface reuses Coding Agents' recall/reflect selection and retries, page roster cadence, and page handlers. It exposes `hindsight_diagnose`, `hindsight_list_pages`, `hindsight_search_pages`, `hindsight_read_page`, `hindsight_reflect`, and `hindsight_sync_status`; it does not expose the old native provider's `hindsight_recall` or `hindsight_retain`. The read adapter rejects ingest, initiative and delete calls even if invoked directly. Sync status reports bank-side state, not a local Git completeness verdict. It does not execute Git. Its operation count is a bounded, non-atomic observation: if pagination cannot account for the declared total (including queues with more than 400 rows), it reports `activeOps: null` and `synced: false`. Automatic context contains bounded historical data, not upstream instructions to write memory. The shared `recallOptions` and `reflectBudget` apply, subject to local deadlines and response bounds. A tool call without a task-local Hermes session id stays inactive rather than using a process-global fallback. Page reads take current `kp-…` node IDs, not reserved endpoints or legacy slugs. Auto-injection on a resumed, branched, or compacted transcript is suppressed because that transcript may already carry its original memory injection; the roster and manual tools remain read-only. First-reflect deferral requires a recognized local HEAD and confirmed empty bank. Unrecognized Git layouts do not defer it.
