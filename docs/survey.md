# Git seed and survey ownership

**Keep Codex as the only seed and survey writer for existing shared banks.** Hermes may read their pages and, when separately approved, retain conversations under its own session IDs. The common Coding Agents `autoSeed` setting does not give Hermes ownership. Do not add any shared or Codex-managed bank to `seed_bank_ids`.

For a dedicated Hermes-owned bank, set the coding profile's local policy to `writes: true`, `seed: true`, and `seed_bank_ids: ["<exact dedicated bank ID>"]`. Keep `survey: false` and `manage_bank_config: false`. The bank must already have `gitlog` configured, and the shared config must resolve to `autoSeed: true` and `gitIngest: message`. The adapter does not create or patch the bank, seed pages, backfill chats, or ingest diffs. `none` and `full` never launch a seed worker. Gitlog updates use the upstream message window and canonical `gitlog:<repo>` document. A conflicting existing owner marker or unresolved prior operation stops the update. The owner marker and local lock prevent this adapter from confusing same-name repositories; they are not a distributed lease recognized by Codex, so the operator must not run both seed writers against the same bank.

The checked-out main repository must have a supported local SHA-1 object graph. The worker reads from a bounded private Git snapshot, not the repository's config, hooks, remotes, or alternates. Oversized histories and unsupported layouts may still route for reads but do not seed. The host rejects commit-message snapshots that trigger its egress credential scrubber rather than sending a modified snapshot. The same scrubber checks the bank ID and the repository name used in the request path, document ID and context. These are safeguards, not a complete secret detector: review and opt in only to history that can be stored in that bank. Seed runs after an eligible completed turn on the Hermes memory manager's tracked worker; it never spawns detached `deepen.js` from a prompt. The worker requests a fresh authorization from the parent immediately before each POST. Revocation before this handoff prevents submission; it cannot recall a request already handed to HTTP. An explicit rejection of a new attempt restores the previous claim. An ambiguous receipt permits replay only for the same snapshot and operation ID; a newer HEAD waits until the older claim is resolved.

**Hermes does not run surveys.** Setting `survey: true` does not start an agent. Native survey execution would be a separate opt-in and acceptance item: a read-only Hermes worker, memory disabled, bounded time and model budget, an ownership lease, and no baseline written when findings fail validation. Do not invoke `codex exec` or impersonate Codex to produce a Hermes survey.
